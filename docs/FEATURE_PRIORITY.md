# Feature priority

## MVP (ship first)

| Feature | Reasoning |
|--------|-----------|
| Mobile-first public page | Matches QR, in-person use, and speed priority. |
| Read + one primary action | Directly matches interview (A & B for client behavior). |
| Owner password + edit screen | Explicit requirement; enables cross-device updates. |
| QR + public URL | Primary acquisition path is QR. |
| Simple totals | Matches “how many used / completed” without enterprise reporting. |
| No client accounts | Keeps friction low; explicit choice. |
| Single shared experience | Scope control; avoids multi-tenant complexity in MVP. |

## Phase 2 enhancements

| Feature | Reasoning |
|--------|-----------|
| Draft/publish, preview | Reduces fear of publishing mistakes. |
| Password recovery | Operational necessity at scale. |
| Better analytics splits | Time-of-day, device class, referrer—when traffic grows. |
| Abuse protection / rate limits | Important if links become public beyond QR context. |

## Future ideas

| Feature | Reasoning |
|--------|-----------|
| Multiple client journeys / A-B | Marketing optimization; not MVP. |
| Payments, scheduling providers | Integrations add compliance and scope. |
| Team accounts & roles | Organization-wide workflow. |

**Reasoning summary:** MVP is a **focused conversion page** with **owner control** and **honest aggregate stats**—not a platform.
